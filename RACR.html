01

这份工作簿在讲什么

文件总体结构、主要指标和快照规模

业务背景

2024 年起，Amazon 把美国可分类商品的交叉转运（IXD）网络分成五个区域： WestCoast、Central、MidAtlantic、NorthEast、SouthEast。每个区域的需求尽量由该区域内的 FC 与 IXD 满足，供应商把货发到靠近 regional cross dock（rIXD）的位置可以加快货物到达和上架。

对供应商的要求是：每周尽量按采购订单全额确认；不能全额确认时，要按各区域 PO 规模等比例确认； 某一周确实无法补的，下一周优先补，避免该区域库存不足。ACR 就是用来衡量这些采购订单确认表现的指标。

工作簿核心概念

JIT = Just-in-Time，即每周补货订单；Non-JIT 包括 Forward、Discounted Bulk、Reactive 等非 JIT 采购。 工作簿分别给出 JIT 与 Non-JIT 的 ACR，并区分当前周、过去 6 周（T6Wks）、过去 12 周（T12Wks）。

ACR 与 VCR 的差别在于：ACR 对一个 ASIN 一周内的重复下单做去重处理，因此当供应商收到多次 PO 且前期 没有全额确认时，ACR 比 VCR 更能反映真实供应缺口。

ACR = total confirmed units / (total confirmed units + last submitted units - last confirmed units)

03

ACR 与 VCR 的差别

FAQ 3 的原始示例

示例：一周重复下单

日期Submit qtyConfirm qty
Sunday00
Monday10025
Tuesday750
Wednesday750
Thursday750
Friday7525
Saturday00

该周总提交 400，总确认 50；但 Amazon 对该 ASIN 的目标需求只有 100，ACR 应反映 50/100。

两种口径

VCR = total confirmed units / total submitted units = 50 / (100+75+75+75+75) = 12.5%
ACR = 50 / (50 + last submitted 75 - last confirmed 25) = 50 / 100 = 50%

供应商每天收到补货 PO 时，如果当天不能全额确认，后面几天 Amazon 会继续下单补足；按全部提交量算 VCR 会被重复订单稀释，ACR 能更准地衡量供应缺口。

Detailed rIXD Data 的区域行分布

同一 ASIN 会同时出现在 National 与多个区域/rIXD 行，因此区域行数和 ASIN 数不是同一概念。

如何看这些数字

先把 ACR 当前周与 T6/T12 比较：只有当前周低，说明是近期缺货或确认不及时；长期低则要看需求预测、产能或商品资料问题。

再看 Submitted Units：它代表经过 ACR 去重后的“应确认数量”。Confirmed Units 少且 Unconfirmed Units 高，说明缺口仍存在。

Non-JIT ACR 主要反映 Forward、Reactive 等批量订单是否被接受，不作为每周补货的主要标准。

Overview

Overview 包含：报告周期、如何使用、每个 Sheet 的一句话描述、Key terms and definitions、FAQ 1 的区域/rIXD 表，以及 FAQ 2/3 的订单类型与 ACR/VCR 解释。

它的区域静态表只用于说明。区域和 rIXD 的映射“会变化”，因此后面工作表的公式结果才代表当期实际归属。

Overall Trend

展示过去 6 周 ACR、Confirmed Units 与 Submitted Units，支持按 ib_region、order_type、vendor code、order_source 筛选。

先看全国，再看五个区域：若某区域 ACR 连续走低，就去 Regional IXD performance 查是哪个 rIXD。

Regional IXD performance

当前周 JIT ACR、JIT Submitted Units、JIT Confirmed Units，按五个区域的 Overall 和区域内 rIXD 列出。

它只算 JIT，因为每周补货确认是最直接影响库存在途的环节。Overall 行的公式按 Chart Data Week 的 ib_region 汇总；代码行的公式只按 rixd 代码汇总，不看代码在表格里被放在哪个区域组下。

Detailed rIXD Data

字段分组：Product Identity（ASIN、External ID Type、External ID、Vendor Code）、Location（Region、rIXD）、JIT/Non-JIT ACR、Unconfirmed Units、Submitted Units。

Current Week 为本周口径，T6Wks/T12Wks 为滚动口径。rIXD 为空或 Region 为 National 的行表示全国网络/全国 FC，不是某个 rIXD。

Detailed Overall Data

没有 Region/rIXD 维度，只按 Product Identity 汇总全网络 JIT/Non-JIT ACR 与数量。

用法：如果某个 ASIN 在全国 Overall 低、但只在特定区域低，则先按区域缺货处理；如果全国都低，则可能是供应总量或商品标识问题。

Chart Data Week

字段：order_week、vendor_code、rixd、order_type、order_source、ib_region、submitted_qty、confirmed_qty、recent_submitted_qty、recent_confirmed_qty。

Regional IXD performance 的 JIT Submitted Units 实际是 confirmed + recent_submitted - recent_confirmed，也就是 ACR 分母，不是 Chart Data Week 原始的 submitted_qty。

Defect 1-3：判据、数据与建议动作

本快照内 0 个 Defect 3 行

Defect 1：区域确认比例不均衡

判据：过去 4 周 Amazon 已向 1 个以上收货区域提交 PO，但 ASIN 对该指定区域/rIXD 的确认量相对其他区域不成比例。

Recommended action：每周尽量全额确认 PO；无法全额确认时，按各区域 PO 规模等比例确认；某区域当周确实无法满足时，下一周优先补该区域，保证区域库存可用。

Defect 2：确认量低于均值需求预测

判据：过去 6 周 Confirm Qty < Mean Demand Forecast。所用 forecast 是下订单周前 6 周共享的预测，并用 VLT 换算需求期。

Recommended action：确保高订单量 ASIN 的库存覆盖至少达到 mean (p50) forecast，避免缺货和高 ROOS。

Defect 3：SKU 标识缺陷

本文件该 Sheet 没有数据行，判据仍在原表保留。

条件组 1：存在未完成产品订单、ASIN 在该 External ID 过去 36 个月没有确认记录、但在另一个 External ID 有确认记录，说明商品可能用了错误的条码/External ID。

条件组 2：商品因 invalid product ID 被 soft-reject，且该 External ID 过去 36 个月未确认过。

Recommended action：通过 Vendor Central 的 Contact us 选择 Manage my catalog，使用 Item ID update 提交匹配正确 External ID 的 Case。
08

每周处理清单

先做判断

  • 查看 Overall Trend：全国和五个区域 JIT ACR 相比 T6/T12 是否下降。
  • 查看 Regional IXD performance：找出低于区域 Overall 的 rIXD。
  • 用 Detailed rIXD Data 定位 ASIN 与未确认数量。

再采取动作

  • 每周把 PO 尽量全额确认，做不到就按区域 PO 规模等比例确认。
  • 缺货区域下一周优先补货。
  • Defect 2 的 ASIN 维持至少 p50 forecast 的库存覆盖。
  • Defect 3 的条码/External ID 问题用 Item ID update 提 Case。
